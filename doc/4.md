## **Slide 3 — Data Bottleneck**

Modern object detection systems are extremely data-hungry — they require massive amounts of well-labeled images.
 But in practice, collecting and annotating diverse real-world scenes is both **expensive and time-consuming**.
 Even after all that effort, datasets are rarely balanced.
 Common situations, like clear daytime driving, appear in abundance, while rare but safety-critical ones — such as fog, night, or emergencies — are scarce.
 This imbalance, known as the **long-tail problem**, creates a major data bottleneck.
 As a result, models perform well on frequent cases but struggle to generalize to rare or unseen scenarios.

------

## **Slide 4 — Traditional Methods**

Researchers have explored several methods to overcome the data bottleneck.
 First, **traditional augmentation** techniques like rotation, cropping, or pixel mixing can slightly improve diversity, but they only modify existing images — they can’t create new or unseen scenes.
 Second, **simulation-based datasets**, like GTA-V, automatically generate labeled scenes at scale. However, these images often appear overly clean or artificial, lacking the natural lighting and textures of real photographs.
 Finally, **domain adaptation** techniques try to make synthetic images look more realistic by transferring styles, but some visual inconsistencies always remain.

Despite these efforts, the gap between synthetic and real data remains. This is where modern generative models start to make a difference.

------

## **Slide 5 — Controllable Diffusion Models**

Recent advances in **diffusion models** have opened a new path for data generation.
 Unlike traditional augmentation, these models can actually *create* new and realistic scenes, instead of simply transforming existing pixels.

**ControlNet** plays a key role by injecting structural information — such as edge maps, depth maps, or segmentation layouts — so that the generated images maintain accurate spatial relationships and respect the original layout.

**Low-Rank Adaptation**, Originally developed for large language models, LoRA was designed to fine-tune massive networks efficiently by updating only a small number of parameters instead of retraining the entire model. This idea has since been successfully transferred to diffusion models, allowing them to adapt quickly to new visual domains. For instance, converting daytime scenes into foggy or nighttime environments — without full retraining.



Together, these components make diffusion models both controllable and adaptable, enabling the generation of realistic and diverse training data tailored for object detection.

## **Slide 6 — Research Objectives **

Building on these ideas, this research focuses on four main objectives.
**quantify the domain gap** between real and synthetic data using multiple visual and semantic metrics.
**evaluate cross-domain robustness**, examining how well models trained with generative data perform when applied to real-world images.
**assess the realism and annotation consistency** of generated samples, ensuring they are both visually convincing and semantically accurate.
**develop best practices** for using generative data effectively in object detection training pipelines.

And additionally, **Identify the contribution of individual components** in the generative augmentation pipeline through **ablation studies**.

------

## **Slide 8 — Research Framework**

The research follows a four-stage framework: **generation**, **filtering**, **training**, and **evaluation**.

In the generation stage, diffusion models enhanced with ControlNet and LoRA are used to produce controllable and adaptive synthetic data. The filtering stage then selects high-quality samples using visual and semantic metrics such as **CLIP**, which measures image–text alignment, and **DINOv2**, which captures semantic similarity between visual features.

Training proceeds with different ratios of real and synthetic data, while the evaluation stage measures both visual quality and detection performance. The feedback from each stage is used to refine the generation process, to make sure improvements are measurable and repeatable.

------

## **Slide 9 — Generation Pipeline**

The generation pipeline is implemented using ComfyUI, a modular and node-based workflow system that supports flexible and reproducible design.

We start with an **original image**, which is first converted into a **Canny edge map**.
That edge map is then fed into **ControlNet**, guiding the model to make a new image with the same layout.

Next, **LoRA** helps adapt the model to different domains — for example, turning a daytime highway scene into a realistic nighttime or foggy version — without the need for full retraining.

Finally, we **reuse the original bounding-box annotations** and apply them directly to the generated image.
This way, we can automatically create realistic and well-labeled data at scale, greatly reducing the need for manual labeling.

Together, these steps make the pipeline both flexible and efficient for object detection training.

------

## **Slide 10 — Training **

After generating the synthetic dataset, we move to the downstream task.
 Here, I focus on two representative object detectors: **YOLO** and **RT-DETR**. These models balance accuracy and real-time efficiency, making them suitable for practical applications like self-driving.

The **training strategy** involves mixing real and synthetic data in different ratios — from entirely real to heavily synthetic — to explore how generative data contributes under various levels of limited data.

The main **objective** of this stage is to quantify the value of synthetic data and identify the most cost-effective balance between real and generated samples. This helps determine how much real data can be replaced without significant performance loss.

## Slide 11 — Evaluation

After training, the models are evaluated through multiple perspectives to understand both task performance and data quality.

For **detection performance**, I use standard object detection metrics such as *mean Average Precision (mAP)* and *AP50*, which directly measure how well the model finds and locates objects. These are task-oriented indicators that reflect real-world performance.

Next, **perceptual quality** is assessed using *FID* and *IS* scores to evaluate the fidelity and diversity of the generated images. Lower FID and higher IS values indicate more realistic and varied results.

To measure **semantic consistency**, I use *CLIP* and *DINOv2* similarity scores, which capture how well the image content aligns with its intended labels or descriptions.

*(Here on the slide, you can see examples of generated images with different semantic scores. Images with higher CLIP and DINOv2 scores appear more faithful to the intended object or scene.)*

Finally, **human evaluation** complements these automated metrics. Participants rate the realism and annotation accuracy of generated samples, providing human insights that pure numerical scores may miss.

Together, these layers of evaluation reveal how visual quality relates to real detection performance, offering a comprehensive understanding of data usefulness.
