# Detection Workflow

## Overview
- YOLOv8-based training pipeline for the scooter detector that relies on the synthetic data scored in `code/generation`.
- `build_yolo_dataset.ipynb` rebuilds a YOLO-format dataset by mixing original labels with the top-ranked synthetic crops stored under each sample’s `scores.json`.
-  `grid_experiment_min.py` provides single-run to train model  and record metrics to `grid_metrics_*.csv`.

## Directory Layout
- `data.yaml` – YOLO data definition pointing to `workdir/train`, `workdir/valid`, and `../dataset/test`.
- `grid_experiment_min.py` – minimal script to run the YOLO model and log results in CSV form.
- `build_yolo_dataset.ipynb` – interactive dataset builder; reuses the helper functions defined at the top of `grid_experiment_min.py`.
- `grid_metrics_*.csv` – historical experiment logs (clip-only, DINO-only, mixed, random, etc.).
- `workdir/` – regenerated YOLO dataset for the next run; cleared/recreated before each experiment.

## Prerequisites
- Python 3.10+ with `ultralytics` and `pandas` installed (see pip command below).
- A populated `../dataset` directory following the structure described below, including `scores.json` files generated by `CLIPMinRanker`.

## Source Dataset Layout
The helpers expect each split to ship the original YOLO annotations plus synthetic candidates ranked by CLIP/DINO:

```bash
dataset/
  train/
    original/
      images/*.jpg
      labels/*.txt            # standard YOLO box format
    synth/
      <image_stem>/
        scores.json           # {"items": [{"index":0,"clip_score":...,"dino_score":...}, ...]}
        <image_stem>_00.png
        ...
  valid/
    original/...
    synth/...
  test/
    images/
    labels/
```

`scores.json` mirrors the output of `code/custom_node/clip_min_ranker.py`; `process_split` reads each `items` entry and ranks it by `clip`, `dino`, `mixed`, or `random`.

`data.yaml` is already committed with the expected staging layout:

```yaml
path: .
train: workdir/train
val: workdir/valid
test: ../dataset/test
nc: 1
names: ['scooter']
```

## Build a YOLO dataset (`build_yolo_dataset.ipynb`)
1. Edit the constants in Cell 2 (`ROOT`, `OUT`, `SPLITS`, `INCLUDE_REAL`, `TOPK`, `SORT`, `ALPHA`) so they match the dataset you want to assemble.
2. Run the helper definitions (Cell 1) once to make `ensure_dir`, `clear_dir`, `process_split`, and `rank_items` available in the notebook.
3. Execute the final cell to call `process_split` for each split. The script:
   - clears `workdir/`,
   - optionally copies the original image/label pairs when `INCLUDE_REAL=True`,
   - ranks the synthetic alternatives inside `<split>/synth/<stem>/scores.json`,
   - copies the top-`TOPK` images into `workdir/<split>/images` while duplicating the original label into `workdir/<split>/labels`.
4. The resulting dataset is ready for Ultralytics; adjust `data.yaml` only if you relocate `workdir`.

The same helper stack is reused by the batch/grid utilities so behavior stays consistent everywhere.



## Batch & Grid Experiments
### `grid_experiment_min.py`
A pure-Python version of the same sweep for long unattended runs.

Key parameters near the top:
- `ROOT`, `OUT`, `SPLITS`, `SORT`, `ALPHA`
- Training knobs: `EPOCHS`, `IMGSZ`, `BATCH`, `WORKERS`, `SEED`, `PROJECT`, `BASE_WEIGHTS`, `DATA_YAML`
- Search space: `include_real_opts`, `topk_opts`

Execution flow per combination:
1. Clear and rebuild `workdir/` with `process_split`.
2. Count images via `count_images` and skip any configuration that would yield empty train/val splits (an entry with `SKIPPED_EMPTY_DATASET` is appended to the CSV).
3. Train `YOLO(BASE_WEIGHTS)` with the configured hyperparameters and save artifacts to `runs_grid/<run_name>`.
4. Validate on the `test` split (`model.val(..., split="test")`).
5. Merge `res.results_dict` with metadata (include_real, topk, sort, alpha, dataset sizes) and append it to the CSV.



Resume or branch a search by editing the constant lists and choosing a new CSV filename.

## Outputs & Logs
- `workdir/` – current YOLO dataset; safe to delete when not training.
- `grid_metrics_*.csv` – consolidated metrics ready for spreadsheets or dashboards; each row stores Ultralytics metrics (mAP, precision, recall, etc.) plus the data-mix metadata.
